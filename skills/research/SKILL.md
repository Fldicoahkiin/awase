---
name: research
description: "Before producing something, collect what only this product, person or project has, and what the field already knows, so the result is built from real material instead of the average. Use before design, copy, docs or writing, or when invoked as awase:research."
---

1. **Reader.** Who uses or reads the result, in what situation, wanting what. Find evidence: the product itself, its users' own words, support threads, analytics the human can share.
2. **Raw material.** Collect the specifics only this case has: real screens, real copy, data, code, the human's own assets and stories, the constraint that makes this case different. If a fact the reader needs is missing, ask the human for it. Do not invent specifics.
3. **The field.** The standards and established patterns for this kind of thing, from primary sources you have opened.
4. **The common version.** How most current examples of this kind of thing look and read. Name it so the result can be judged against it; this list goes to whoever reviews the result. The producer does not see it, so the result is not built toward it.

Report each with its source. List what you looked for and did not find, with where you looked, so a gap reads as a gap and not as something that doesn't exist. Date the report; a later run on the same subject is compared against it to see what changed. The output is material for a brief. Save it to a file the human names.
